# V2 大文件断点续传更新计划

## 状态与目标

本文档最初描述下一阶段计划；Adaptive V2 的 1 MiB 检查点、恢复协商、`--resume` 与 `--restart` 现已实现。本文保留为设计与验收记录。

目标是在 Adaptive V2 模式下支持 ZIP、PDF 等任意大文件的断点续传：传输中断后保留已经校验成功的数据；再次发送同一文件时，接收端验证本地进度并与发送端协商恢复偏移，只重传尚未完成的部分。

Legacy 协议保持不变，不支持断点续传。

## 使用方式

发送端和接收端新增显式参数 `--resume`：

```powershell
java -jar .\qrtransfer-cli-1.0-SNAPSHOT.jar send `
  --input "<输入文件路径>" `
  --profile fast `
  --resume
```

```bash
java -jar ./qrtransfer-cli-1.0-SNAPSHOT.jar receive \
  --output "<输出文件路径>" \
  --profile fast \
  --resume
```

- 首次传输和恢复传输使用相同命令。
- 只有输入文件内容和接收输出路径需要保持一致；profile、二维码尺寸和页面大小可以调整。
- 未指定 `--resume` 时继续使用当前临时文件行为，中断后不承诺保留进度。
- 指定 `--resume` 时，接收端使用固定文件：

  ```text
  <输出文件>.part
  <输出文件>.part.meta
  ```

- 如果已存在最终输出文件，仍遵守当前 `--overwrite` 规则。
- 新增 `--restart`，用于明确删除与本次输出对应的旧断点并从零开始；不得静默覆盖不匹配的断点。

## 文件身份与本地检查点

`.part.meta` 至少记录：

- 元数据格式版本；
- V2 协议版本；
- 源文件总大小与完整 MD5；
- 已提交的字节偏移；
- 检查点块大小，默认 `1MiB`；
- 每个已完成检查点块的 MD5；
- 文本标志和最近更新时间。

接收端只把通过 V2 帧 CRC32C、会话 ID、页号和偏移检查的数据写入 `.part`。每完成 `1MiB`：

1. 刷新 `.part` 数据；
2. 计算并记录该检查点块的 MD5；
3. 将新元数据先写入临时文件，再原子替换 `.part.meta`。

启动恢复时：

1. 校验元数据格式、源文件总大小和完整 MD5；
2. 逐个验证已记录检查点；
3. 将 `.part` 截断到最后一个验证成功的检查点；
4. 未满一个检查点的尾部不作为已提交进度，最多重传约 `1MiB`；
5. 元数据损坏、源文件变化或任何检查点不一致时拒绝续传，保留现场并提示使用 `--restart`。

MD5 用于检测意外传输和存储错误，不提供恶意碰撞防护、加密或身份认证。

## 恢复协商与协议扩展

在现有 V2 文件头、数据页和确认按键之外增加 `RESUME_READY` 与 `RESUME_CONFIRM` 两种帧，不改变已有文件头和数据页编码：

- 发送端显示文件头时，按键 `1` 继续表示从零开始，按键 `6` 表示请求进入恢复状态。
- 收到 `6` 后，发送端显示 `RESUME_READY`；接收端没有识别到该帧前不得发送检查点编号。
- `RESUME_READY` 状态下，发送端将数字键 `0–9` 解释为十进制检查点编号，`Enter` 表示提交，`Escape` 表示取消并返回文件头。
- 提交后发送端显示 `RESUME_CONFIRM`，内容包括检查点编号、恢复偏移、源文件大小、完整 MD5、恢复前缀 MD5 和新会话 ID。
- 接收端按 `7` 接受确认并开始续传，按 `8` 拒绝并返回 `RESUME_READY` 重新输入。

发送端必须在 `RESUME_CONFIRM` 中回显完整解析结果。按键丢失、焦点错误、空编号或编号越界时不开始数据传输，接收端重新按 `6` 发起协商。协商超时或对端不支持 `RESUME_READY` 时明确失败，不静默退回从零发送。

发送端收到确认后：

- 从确认偏移打开输入文件；
- 新会话的数据页从页号 `0` 重新编号，但首个数据页的 offset 等于恢复偏移；
- 重新执行当前 profile 的页面大小校准和自适应逻辑；
- 计算源文件对应前缀的 MD5，并在开始传输前与接收端计算的 `.part` 前缀 MD5 比较；
- 源文件在准备或传输期间发生大小、时间戳或内容变化时立即失败。

接收端收到恢复后的数据页时，以恢复偏移作为 `expectedOffset`，继续追加到 `.part`。最终仍必须同时通过总大小和完整文件 MD5，校验成功后才原子移动为最终输出。

## 中断与清理

- `Ctrl+C`、窗口关闭、识别超时和远程桌面断开时，保留最后一个已提交检查点。
- 不完整检查点允许保留在文件尾部，但下次恢复前必须截断。
- JVM 正常退出时关闭并刷新文件，不再由 shutdown hook 删除 resumable `.part`。
- 未使用 `--resume` 的传输继续沿用当前随机临时文件及失败清理策略。
- `--restart` 只删除明确输出路径对应的 `.part` 和 `.part.meta`，不得扫描或递归删除其他文件。
- 完成后删除 `.part.meta`；`.part` 原子移动为最终输出文件。

## 日志与统计

启动时打印：

- 是否发现断点；
- 原始断点大小、验证后的恢复偏移和需要回退的字节数；
- 源文件身份是否匹配；
- 协商成功的恢复偏移。

完成统计增加：

- 本次新传字节数；
- 从断点复用的字节数；
- 回退重传字节数；
- 本次耗时和本次有效速度；
- 包含历史断点后的总完成比例。

不得在日志中输出文件内容。

## 实施顺序

1. 实现固定 `.part`、原子元数据和检查点校验，不修改协议。
2. 扩展 V2 恢复帧与可靠按键编号协商，发送端支持从任意检查点偏移读取。
3. 将恢复流程接入统一 CLI 的 `send`、`receive`、`--resume` 和 `--restart`。
4. 增加恢复统计、README 使用说明和协议文档。
5. 在确认 V2 完整回归后生成新的统一 CLI JAR；旧 JAR 和 Legacy 行为保持兼容。

新发送端与未使用 `--resume` 的旧 V2 接收端仍通过按键 `1` 从零开始。启用 `--resume` 时要求两端都是支持恢复协议的新版本；任一端不支持时直接报错。

## 测试与验收

- 单元测试：元数据读写、原子替换、检查点生成、尾部截断、源文件不匹配和元数据损坏。
- 协议测试：恢复编号丢键、重复键、越界、错误回显、重复恢复确认和不同会话帧。
- 续传测试：分别在文件头、第一个检查点中间、多个检查点后和末页前中断并恢复。
- 完整性测试：修改 `.part`、修改源文件、伪造长度、CRC 错误和最终 MD5 错误时不得发布最终文件。
- 参数测试：`--resume`、`--restart`、`--overwrite`、`--text` 和三个 profile 的组合行为。
- 端到端验收：大 ZIP 中断后再次运行相同命令，日志显示非零复用字节，只传剩余部分，最终文件大小与 MD5 均与源文件一致。
- 回归测试：未加 `--resume` 的 V2 行为、Benchmark、Legacy、当前自适应升降密和速度统计全部保持不变。

## 默认约束

- 首版仅支持单个输出路径对应一个断点，不支持同时恢复多个来源到同一输出路径。
- 断点不能跨不同内容文件复用；文件名相同但大小或 MD5 不同也视为不同文件。
- 默认检查点为 `1MiB`，优先减少元数据写入和摘要计算开销。
- 断点续传只保证意外错误可检测，不绕过远程桌面或组织的数据传输策略。
